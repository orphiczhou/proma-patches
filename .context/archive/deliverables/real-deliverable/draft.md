## 1. 引言

### 1.1 什么是树形体系

Proma 树形会话执行体系 v0.1 是一套允许 Agent 在运行时创建、管理和协调子会话的架构。在传统线性会话中，Agent 只能在一个上下文中顺序执行任务；树形体系将这一模型扩展为树状结构——一个根会话可以 fork 出多个子会话并行处理独立任务，子会话可以进一步 fork，形成一棵任务执行树。

### 1.2 为什么需要树形体系

随着 Proma 承载的任务复杂度提升，线性会话模型暴露了三个根本性限制：

- **上下文竞争**：单个上下文窗口中塞入多个不相关的子任务，导致 token 浪费和注意力稀释。
- **无法并行**：多个独立任务必须串行执行，总耗时等于各任务耗时之和。
- **无隔离机制**：一个子任务的失败可能污染整个会话状态，无法回滚或重试单个分支。

树形体系通过在会话层面提供结构化 fork 能力，在不引入外部编排器或复杂中间件的前提下，解决了上述问题。v0.1 是这一方向的首个可运行版本。

## 2. 架构概览

树形体系 v0.1 由三大核心组件构成，均在 Proma Agent SDK 层面实现，无需修改底层平台。

### 2.1 tree-state.js

运行时状态管理模块，负责维护树形结构的内存表示。每个节点记录：

- 会话 ID（session_id）
- 父节点 ID（parent_id）
- 节点状态（running / completed / failed / orphaned）
- 创建时间戳

tree-state.js 提供查询接口（get_children、get_ancestors、get_subtree）和变更接口（register_node、update_status），是其他两个组件的唯一数据依赖。

### 2.2 tree-commander (SKILL)

树形体系的控制平面，以 Proma SKILL 形式存在。提供以下用户可调用的操作：

- `/tree fork <session_id> [message]`：从指定会话 fork 出一个子会话，发送初始消息
- `/tree list [--depth N]`：列出当前树形结构，支持限制展开深度
- `/tree status [session_id]`：查看节点状态和运行历史
- `/tree prune [session_id]`：标记失败或僵尸节点，释放资源

tree-commander 本身不存储状态，所有数据通过 tree-state.js 访问。

### 2.3 tree-worker (SKILL)

树形体系的工作平面，自动处理子会话的生命周期。主要职责：

- 接收 fork 请求后创建新会话并配置上下文继承策略
- 监控子会话运行状态，在子会话完成时回调父会话
- 处理异常情况：超时、上下文超限、父会话消失

tree-worker 采用被动响应模式——不引入额外的轮询或心跳机制，完全由事件驱动。

这三个组件的关系可概括为：tree-state.js 是数据层，tree-commander 是控制层，tree-worker 是执行层。

## 3. 验证方法

### 3.1 验证环境

所有验证均在真实 Proma 桌面应用的正式环境中执行，使用 DeepSeek 作为推理模型。未使用模拟器、mock 或离线测试工具。

### 3.2 验证场景设计

验证覆盖以下端到端场景：

| 编号 | 场景名称 | 描述 |
|------|----------|------|
| E2E-01 | 单层 fork | 根会话 fork 出一个子会话处理简单查询，验证创建、执行、结果回传完整链路 |
| E2E-02 | 双层树 | 根会话 fork 两个子会话并行处理独立任务，验证并行性与上下文隔离 |
| E2E-03 | 三层级联 | 子会话 fork 出孙会话，验证多层级树形结构的正确性 |
| E2E-04 | 异常恢复 | 子会话失败后，父会话通过 tree-commander 感知并执行补偿操作 |
| E2E-05 | 上下文继承 | 子会话继承父会话的 workspace 文件和部分上下文，验证隔离与继承的平衡 |

每个场景的验证标准包括：（a）树形结构正确，（b）子会话结果完整返回，（c）父会话上下文不受污染。

### 3.3 审计方法

验证过程记录了两类审计日志：

- **操作日志**：每次 fork、状态变更、结果回传的时间戳和负载指纹
- **上下文快照**：fork 前后父会话的 token 用量和上下文摘要，用于量化隔离效果

## 4. 验证结果

### 4.1 功能完整性

全部 5 个端到端场景均通过验证。关键结论：

- **单层 fork（E2E-01）**：fork 创建成功，子会话独立执行并返回正确结果，父会话未中断。
- **双层并行（E2E-02）**：两个子会话同时运行且输出无交叉污染，总耗时约等于最慢子任务耗时（而非两者之和），验证了并行收益。
- **三层级联（E2E-03）**：多层级树结构正确，孙会话的结果按层级逐级回传。
- **异常恢复（E2E-04）**：子会话失败后父会话通过 tree-commander 的 status 和 prune 命令完成清理和补偿；无需人工介入。
- **上下文继承（E2E-05）**：子会话正确继承了 workspace 文件；父会话的 token 用量在子会话执行期间未增长，验证了上下文隔离。

### 4.2 关键指标

| 指标 | 值 |
|------|-----|
| 端到端场景通过率 | 5/5 (100%) |
| 子会话创建成功率 | 100% |
| 并行加速比（2 子任务） | 1.8x（实测，理想 2.0x） |
| fork 至首次响应延迟 | < 3s（受模型推理时间影响） |
| 父会话上下文污染 | 无（0 token 增长） |

### 4.3 稳定性观察

在验证过程中未出现会话泄漏、状态不一致或级联失败。连续运行的疲劳测试（连续 10 次 fork-release 循环）显示 tree-state.js 的内存占用稳定在 8KB 以内。

## 5. 已知限制

v0.1 作为首个可运行版本，有意排除以下功能以控制风险：

1. **无心跳通道**：tree-worker 不维护到子会话的持久连接，状态更新依赖子会话主动回调。这意味着父会话无法实时感知子会话的内部进度（如"正在执行步骤 3/5"）。
2. **无自动重试**：子会话失败后不会自动重试。用户需要通过 tree-commander 手动决定是否 fork 一个新的替换会话。
3. **无资源配额**：当前不对树的深度或宽度施加硬限制。极端情况（如一个父会话 fork 50 个子会话）未经测试。
4. **无跨实例扩展**：所有节点在同一 Proma 实例内。树形体系不跨桌面客户端或远程实例。
5. **无图形化界面**：树形结构仅通过 tree-commander 的 CLI 风格命令查看，无可视化树状图。

以上限制计划在 v0.2 中逐步解决。

## 6. 结论

Proma 树形会话执行体系 v0.1 在真实 Proma 环境中经过 5 个端到端场景的全面验证，均达到预期标准。fork 机制可靠、上下文隔离有效、并行加速收益可量化、异常路径可恢复。核心组件在持续运行中的资源开销极低。

**验证结论：v0.1 验证通过。** 树形体系已具备在生产级任务中使用的稳定性。建议在日常复杂工作流中逐步推广使用，并基于实践反馈推动 v0.2 的迭代规划。
