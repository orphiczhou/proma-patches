## 关键技术决策（新会话必须知道）

1. **spawn vs require**：tree-state.js 的 `TREES_ROOT=__dirname`（line 110）依赖脚本所在目录定位 tree 数据。require 会把 `__dirname` 变成 dist/（破坏定位）；spawn 时 `__dirname` 天然 = `.context/trees/`（正确）。**所以 MCP 用 spawn 包装，tree-state.js 零改动**。
2. **workspace 定位**：`findTreesDirForWorkspace(workspaceSlug)` 据 `PROMA_INSTANCE_ISOLATED` 判断 dev（`~/.proma-dev/agent-workspaces/`）vs release（`~/.proma/agent-workspaces/`），找 `<ws>/{workspace-files/,}.context/trees/`。注：proma-dev-patches.cjs 里 `discoverAllWorkspacesWithTrees`（line ~1099）是 `registerTreePanelIpc` IIFE 的**局部**函数，模块级 `createTreeMcpServer` 访问不到，故独立实现了一份 `findTreesDirForWorkspace`。
3. **MCP 注册点**：`global.__proma_getMcpServers__`（proma-dev-patches.cjs）return 加 `tree: global.__proma_createTreeMcpServer__(sdk,z,workspaceSlug)`。tree server 用 try/catch 包裹（失败不影响 session/remote）。
4. **auditor 白名单（V2）是 CLI 层极限**：auditor 必须树中真实 leaf session（堵伪造 UUID）。真·独立审计（验证 session 真实运行）需 Layer 4 `subagent_trace_id`（平台层，依赖 Anthropic/Proma 官方）。
5. **自举验证有效**：全程真实 Proma 子会话（`collaboration.delegate_agent`）实施 + 对抗审计。4 个 worker + 1 auditor **全部诚信**（无 sycophancy/reward-tampering），证明"给硬约束后模型可靠工作"——反向验证方案核心论断。继续用此模式。
