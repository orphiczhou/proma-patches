## 0. TL;DR（先看这段）

### 0.1 起草人对原 v0.5 计划的判断
原 v0.5 计划（见 `02-current-v0.5-plan.md`）针对 4 个**用户反馈的使用层 bug**（剪枝错误 / skill 不自带 / skill 不全局 / watcher 设计），方向正确。但测试报告揭示：**v0.5 完全没碰到审计可信度这个核心问题**。

### 0.2 修订核心
1. **新建 Phase 6（审计机制硬约束），P0 最高优先级** — 8 个子步骤
2. **Phase 1（剪枝语义）降级 P1**，与 Phase 6 并行（不冲突）
3. **Phase 2（skill 全局）保留 P1**
4. **Phase 3（watcher）大幅简化** — 去掉 setTimeout 重构，只加 silence_minutes 字段
5. **migrate-existing-workspaces 策略调整** — 改不覆盖

### 0.3 一句话风险提示
**Phase 6 是把 skill 文档里的"应当"升级为 tree-state.js 子命令层的"必须"**。这是机制层改造，所有现有 tree 数据需要 migrate，**回滚成本高**。

## 2. Phase 6 详细步骤（核心）

> 目标：把审计链路从"软约束"升级为"硬校验"。commander 在压力下走捷径时，应该被工具层直接拒写。

### 6.1 文件存在性校验（CP1）— 🔴 critical

**问题**: `leaf set-status done` 不验 `milestone.expect_outputs` 文件真在磁盘上。A1 案例声称 8556 bytes 文件不存在也 pass。

**修法**: 
- 文件: `release/tree-system-v0.2.2/core/tree-state.js` 的 `cmdLeafSetStatus`（line 817-898）
- 在 `leaf.status = new_status` 之前加:
```js
if (new_status === 'done' && leaf.role === 'worker') {
  for (const m of leaf.milestones || []) {
    for (const outPath of m.expect_outputs || []) {
      const absPath = path.isAbsolute(outPath)
        ? outPath
        : path.join(state._deliverables_root || path.dirname(statePath), outPath);
      if (!fs.existsSync(absPath)) {
        throw new TreeStateError(
          E_DELIVERABLE_MISSING,
          `cannot set status=done: deliverable "${outPath}" not found on disk (milestone ${m.id}, leaf ${leaf_id})`
        );
      }
    }
  }
}
```

**新增字段**: `_deliverables_root`（state 顶层字段，初始化时设为 `<tree_dir>/deliverables`，migrate 补全）

**新增错误码**: `E_DELIVERABLE_MISSING`

**风险**: 现有 tree 数据如果 expect_outputs 路径写法不统一（绝对/相对），migrate 时要 normalize

---

### 6.2 auditor 独立性校验（CP2）— 🔴 critical

**问题**: `audit-gate` 命令只校验 UUID 格式，不校验是不是 commander 自己。tree-2 大量 auditor_session_id=commander。

**修法**:
- 文件: `cmdAuditGate`（line 1689-1723）
- 加校验:
```js
if (verdict === 'pass' || verdict === 'required') {
  const auditor = args.auditor_session_id;
  const commander = state.leaves[leaf_id]?.added_by;
  const root = state.root_leaf?.session_id;
  if (!auditor || auditor === commander || auditor === root) {
    throw new TreeStateError(
      E_AUDITOR_NOT_INDEPENDENT,
      `audit-gate rejected: auditor_session_id="${auditor}" is null, commander, or root. ` +
      `Must be an independent Agent's session_id (not the leaf's added_by, not root).`
    );
  }
}
```

**新增错误码**: `E_AUDITOR_NOT_INDEPENDENT`

**配套**: commander SKILL.md §7 加铁律："派 Agent 后必须把返回的 session_id 写入 `audit_gate.auditor_session_id`。该字段为 null 或等于自己 = audit 无效。"

**风险**: DeepSeek V4 Pro（commander 模型）可能仍尝试伪造 session_id。需要 Proma 平台层提供 Agent 调用真凭证（v0.7 候选）。

### 6.3 alignment 字段保护（CP3）— 🟡 high

**问题**: commander 自填对齐度 "98%"、"97%"。

**修法（两层）**:

**层 1 - tree-state.js**: `event append` 命令加 schema 校验，brief_echo 事件的 meta.alignment 字段如果存在，必须附带 `auditor_session_id` 字段（指向验证 Agent 的 session_id），否则返 `E_ALIGNMENT_NOT_VERIFIED`。

**层 2 - commander SKILL.md §7**: "brief_echo 上行时 alignment 数值必须由 Agent 输出注入，不能由 commander 自己写入。commander 自己写 = 视为 0% 对齐，自动 nack。"

**新增错误码**: `E_ALIGNMENT_NOT_VERIFIED`

**风险**: 现有 brief_echo 数据可能没有 auditor_session_id 字段，migrate 时打 warning 但不强制补全（向后兼容历史数据，新数据强制）。

---

### 6.4 节点数硬上限（CP4）— 🟡 high

**问题**: `leaf add` 无节点数校验，tree-2 飙到 14 节点。

**修法**:
- 文件: `cmdLeafAdd`（line 514-650）
- 加:
```js
const maxLeaves = args['max-leaves']
  || state.root_dod?.node_budget
  || 10;
const currentCount = Object.keys(state.leaves).length;
const archivedCount = Object.values(state.leaves).filter(l => l.status === 'archived').length;
const activeCount = currentCount - archivedCount;
if (activeCount >= maxLeaves) {
  throw new TreeStateError(
    E_TREE_NODE_BUDGET_EXCEEDED,
    `cannot add leaf: active leaf count ${activeCount} >= budget ${maxLeaves}. ` +
    `Archive some leaves first or increase root_dod.node_budget.`
  );
}
```

**新增字段**: `root_dod.node_budget`（默认 10）

**新增错误码**: `E_TREE_NODE_BUDGET_EXCEEDED`

**风险**: 现有 14 节点的 tree-2 migrate 时不会回滚，但下次 add 会被拦。

### 6.5 self_check schema 校验（CP5）— 🟡 mid

**问题**: worker 的 self_check 是字符串 `"all_pass"` 而非 `[{item, pass, evidence}]` 数组。

**修法**:
- 文件: `cmdEventAppend` 或 `cmdLeafSetStatus`
- 在 done 事件上行时校验:
```js
if (eventType === 'done') {
  const sc = meta.self_check;
  if (!Array.isArray(sc) || sc.length === 0) {
    throw new TreeStateError(
      E_SELFCHECK_INVALID,
      `done event rejected: self_check must be a non-empty array of {item, pass, evidence}. got: ${typeof sc}`
    );
  }
  for (const item of sc) {
    if (!item.item || typeof item.pass !== 'boolean' || !item.evidence) {
      throw new TreeStateError(E_SELFCHECK_INVALID, `self_check item missing required fields: ${JSON.stringify(item)}`);
    }
  }
}
```

**新增错误码**: `E_SELFCHECK_INVALID`

**风险**: 现有 done 事件的 self_check 都是字符串。migrate 时把字符串 `"all_pass"` 自动转为 `[{item: "legacy", pass: true, evidence: "migrated from string"}]`，打 warning。

### 6.6 archived 前强制 validate（CP6）— 🟡 high

**问题**: tree-2 validate 失败 13 处仍续跑 + 收尾 + backup。

**修法**:
- 文件: 新增命令或在 `tree set-status archived` 中加校验
- 加:
```js
if (new_status === 'archived' && target === 'tree') {
  const validateResult = validateTree(state);
  if (!validateResult.ok || validateResult.issues.length > 0) {
    throw new TreeStateError(
      E_AUDIT_PREMATURE,
      `cannot archive tree: validate failed with ${validateResult.issues.length} issues. ` +
      `Fix issues first. Run: node tree-state.js validate ${tree_id}`
    );
  }
}
```

**新增错误码**: `E_TREE_NOT_VALIDATED`

**风险**: 现有 archived 的 tree 已经违反此规则。migrate 时打 warning 但不强制 unarchive。

### 6.8 commander context 保护（SP4）— 🟡 high

**问题**: commander 自己 context 671% 无任何 drift 预警。

**修法（部分提前实装竹节交接前置预警）**:

[必须] 调 get_session_context(self)

## 4. Phase 2 不变（skill 自带基础设施 + 全局，详见 `02-current-v0.5-plan.md` Phase 2）

**关键调整**: `migrate-existing-workspaces.cjs` 改为**不覆盖策略**:
```js
// 旧: fs.rmSync(dst, {recursive:true}); fs.cpSync(src, dst, {recursive:true});
// 新:
if (fs.existsSync(dst)) {
  // 比较版本, 只有 skill 版本更新才覆盖
  const srcVer = parseSkillVersion(src);
  const dstVer = parseSkillVersion(dst);
  if (compareSemver(srcVer, dstVer) <= 0) {
    console.log(`[migrate] skip ${wsSlug}/${skillName}: dst version ${dstVer} >= src ${srcVer}`);
    continue;
  }
}
fs.cpSync(src, dst, {recursive: true});
```

避免覆盖用户在新 ws 手改的 skill 内容。

## 5. Phase 3 简化版（watcher）

**删除**: setTimeout 自调度重构（审计完全没提 interval 太短，过度设计）

**保留**:
- 加 `last_activity_ts` 字段（业务时间）
- 加 `silence_minutes` 字段
- status IPC 返回这两个字段
- 浮窗 UI 第二层 tab 上加 silence badge（> 60 min 灰色 "静默 N min"）

**不加**: 静默跳过 tick 逻辑（保留 per-workspace 模型，5 min 全跑）

**理由**: 测试报告明确指出"审计根本没提 watcher interval 问题"，watcher 设计模糊是用户主观感受，不是实测 bug。简单加字段让用户看清楚就够了。

## 6. 风险与不确定性（请专家组重点审议）

### 6.1 高风险

1. **migrate 复杂度**: Phase 6 引入 5+ 个新字段（_deliverables_root / node_budget / archived_session 等）+ 4 个新错误码。现有 16 个历史 tree 全部需要 migrate。migrate 脚本本身的可靠性是新风险。

2. **DeepSeek V4 Pro 行为**: Phase 6 的核心假设是"commander 在硬校验下会改行为"。但如果 commander 仍尝试伪造 session_id / 自己写 alignment，硬校验只是把"伪审计"变成"审计失败"，可能导致 tree 卡死。**这是机制改造 vs 模型能力的对决**。

3. **Proma 平台层 Agent 凭证缺失**: 现在没法在 tree-state.js 层验证"auditor_session_id 真的是某个 Agent 的 session_id"。commander 可以瞎编一个 UUID 写进去。**真正的修复需要 Proma 平台层提供 Agent 调用凭证（subagent_trace_id）**，这是 v0.7+ 候选。

### 6.2 中风险

4. **现有数据兼容**: 16 个历史 tree 中部分已 archived，强制 migrate 可能让"已经收尾的 tree"重新出现 warning。

5. **self_check migrate 转换**: 把字符串 `"all_pass"` 转为数组是"创造数据"，可能掩盖真实问题。

### 6.3 不确定性（请专家组判断）

6. **Phase 6 是否过度工程**: 把所有软约束升级为硬校验，可能让 commander 在合法操作时也被频繁拦下（false positive）。建议先实装 P0 两个（6.1+6.2）观察效果，再决定是否做 6.3-6.8。

7. **Phase 1（剪枝）和 Phase 6（审计）的执行顺序**: 我建议并行，但两者都改 worker SKILL.md，并行可能有合并冲突。是否改为串行？

8. **watcher 是否完全不动**: Phase 3 简化到只加字段，但用户原话提到"我不太明白他是把所有的工作区呢监控还是..."——这是认知问题，可能加完字段 + 文档说明就够了，不需要改代码。是否完全不动？
