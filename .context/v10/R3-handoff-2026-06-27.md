## 二、R3 P0-1 修复方案：D2-B1 `added_by` 事前校验

### 目标文件
`D:/Proma-dev/resources/app/dist/tree-engine.cjs`

### 目标函数
`cmdLeafAdd`（行号约 708-840，搜索 `async function cmdLeafAdd`）

### 现状代码（约行 750-757）
```javascript
// v0.2.2-修复#4: 非 root leaf 必须传 added_by（操作者追溯链）
if (role !== 'root') {
  if (!added_by || !UUID_RE.test(added_by)) {
    throw new TreeStateError(
      E_SCHEMA_INVALID,
      'added_by (operator session_id) is required for non-root leaves and must be a valid UUID'
    );
  }
}
```

只校验 `added_by` 是 UUID，不校验是否在树中。

### 修复方案
参考 `cmdEventAppend` 的 Bug A 修复（行 1498）+ `resolveAuditorIndep` 的 root 扩展（行 1978+）。

**插入位置**：在 `withLock` 内部、session_id 唯一性校验之后（约行 791 后）：

```javascript
// V9+ Phase 5 (R3 P0 / D2-B1 修复): added_by 事前校验
//   失守根因：R2 洁净室 D2-B1 暴露 — tree_leaf_add 接受任意 UUID 作为 added_by，
//   仅 tree_validate 事后检测 added_by_not_in_tree。恶意 worker 可伪造 commander 身份。
//   修复：参考 cmdEventAppend 的 Bug A 修复，事前校验 added_by 必须满足以下任一：
//   ① 是树内某个 leaf 的 session_id（合法操作者）
//   ② 是 root leaf 的 session_id（root trust anchor 特权）
//   ③ 是 root 的 added_by（向后兼容历史数据）
if (role !== 'root' && added_by) {
  const isRootLeafSession = Object.values(state.leaves).some(
    (l) => l.parent === null && l.role === 'root' && l.session_id === added_by
  );
  const isExistingLeafSession = Object.values(state.leaves).some(
    (l) => l.session_id === added_by
  );
  if (!isRootLeafSession && !isExistingLeafSession) {
    throw new TreeStateError(
      E_BORROWED_IDENTITY,
      `leaf_add rejected: added_by "${added_by}" not found as any leaf session in tree (possible forged identity). added_by must be the session_id of an existing leaf (typically commander or root).`
    );
  }
  // 额外：禁止 worker 担任 added_by（worker 不能添加子 leaf）
  const addedByLeaf = Object.values(state.leaves).find((l) => l.session_id === added_by);
  if (addedByLeaf && addedByLeaf.role === 'worker') {
    throw new TreeStateError(
      E_BORROWED_IDENTITY,
      `leaf_add rejected: added_by "${added_by}" maps to leaf "${addedByLeaf.leaf_id}" with role=worker (workers cannot add child leaves — only root/commander can).`
    );
  }
}
```

### 回归风险
- ✅ 向后兼容：合法 commander 添加 leaf 仍正常工作
- ⚠️ 测试用例影响：R2 之前的测试可能用 `added_by="00000000-...-000001"` 等占位 UUID，需要处理
- **建议**：增加占位 UUID 跳过逻辑（参考 audit_log_integrity 的 `PLACEHOLDER_UUID_PATTERN`）

```javascript
const PLACEHOLDER_ADDED_BY_PATTERN = /^00000000-0000-0000-0000-[0-9]{12}$/;
// 在 added_by 校验前
if (PLACEHOLDER_ADDED_BY_PATTERN.test(added_by)) {
  // 占位 UUID，跳过事前校验（金标准兼容），依赖 tree_validate 事后检测
} else {
  // 上面的校验逻辑
}
```

## 三、R3 P0-2 修复方案：D2-R3 B5 跨 leaf 注入

### 目标文件
`D:/Proma-dev/resources/app/dist/tree-engine.cjs`

### 双管齐下

#### 3.1 `cmdAuditAppend` 入口加角色检查

**函数位置**：`cmdAuditAppend`（搜索 `async function cmdAuditAppend`，约行 2480-2540）

**现状代码**（约行 2520-2530，校验 auditor 存在性 + 非自身）：
```javascript
const auditorLeaf = Object.values(state.leaves).find(l => l.session_id === entry.auditor_session_id);
if (!auditorLeaf) {
  throw new TreeStateError(E_AUDITOR_NOT_INDEPENDENT, `audit_append rejected: auditor_session_id "..." not found as any leaf session in tree`);
}
if (auditorLeaf.leaf_id === leaf.leaf_id) {
  throw new TreeStateError(E_AUDITOR_NOT_INDEPENDENT, `audit_append rejected: auditor_session_id "..." is the target leaf itself (self-audit forbidden)`);
}
```

**修复**：在 `auditorLeaf.leaf_id === leaf.leaf_id` 校验之后增加：

```javascript
// V9+ Phase 5 (R3 P0 / D2-R3 修复): auditor 角色检查
//   失守根因：R2 洁净室 D2-R3 暴露 — cmdAuditAppend 允许任意非自身 leaf 担任 auditor，
//   包括 worker。worker 可通过 API 路径冒充 auditor 写 audit_log，audit_log_integrity
//   的 role===worker 检查只在 tree_validate 时报告 issue（事后），不在入口拦截。
//   修复：cmdAuditAppend 入口直接拒绝 worker 担任 auditor。
if (auditorLeaf.role === 'worker') {
  throw new TreeStateError(
    E_AUDITOR_NOT_INDEPENDENT,
    `audit_append rejected: auditor_session_id "${entry.auditor_session_id}" maps to leaf "${auditorLeaf.leaf_id}" with role=worker (workers cannot serve as auditors — only root/commander can endorse others).`
  );
}
```

#### 3.2 `collectValidateIssues.audit_log_integrity` 增强

**位置**：约行 2305-2365，新增检查项已有第 ② 项（role===worker）

**现状问题**：D 报告说"未触发"。可能原因：worker 通过 cmdAuditAppend 注入的 audit_log，其 auditor_session_id 实际指向 commander（worker 用 commander 的 session_id）。所以检查 ② auditor role === 'worker' 不触发（因为 auditor 实际是 commander）。

**真正的攻击路径**：worker 冒充 commander 的 session_id（如果能拿到 commander 的 session_id），或 commander 越权审计其他 leaf（commander 是 commander，但只审计指派给它的 leaf）。

**修复建议**：增加"明确指派"机制 — auditor 必须是被审计 leaf 的明确指派（如 leaf.assigned_auditor）

```javascript
// 第 ④ 项检查：auditor 必须是被审计 leaf 的明确指派（如果 leaf.assigned_auditor 存在）
if (leaf.assigned_auditor && entry.auditor_session_id !== leaf.assigned_auditor) {
  issues.push({
    type: 'audit_log_integrity',
    leaf_id: id,
    detail: `audit_log[${i}].auditor_session_id "${auditorSession}" not match leaf.assigned_auditor "${leaf.assigned_auditor}" (auditor must be explicitly assigned to this leaf).`
  });
}
```

**注意**：这需要新增 `leaf.assigned_auditor` 字段 + `tree_leaf_assign_auditor` 工具。是 R3 的可选大改动。

**最小修复**：先做 3.1（cmdAuditAppend 入口加角色检查），能堵住 D 视角的 worker 冒充 auditor 路径。3.2 的"明确指派"机制作为 R3 强化项。

引擎 `leaf_id` 接受 `[a-z][a-z0-9_]{3,7}-<path>-<role>[-<suffix>]`，**不接受连字符**。但 `tree_id` 宽松（接受连字符和长前缀）。

**推荐 tree_id 前缀**：`cr26r3{cmd}`（8 字符内），如 `cr26r3a`、`cr26r3b`
