> 周星星 | 2026-06-16

## 一、战略定位

基于 Proma 开源核心（AGPL-3.0）构建**垂直化 AI 助手产品**，通过闭源模块叠加差异化能力，形成自有品牌和注册体系。

**核心策略：开源做壳，闭源做肉——跟 Proma 商业版走一样的路。**

## 四、许可证合规方案

### 必须开源的部分
- Proma 核心本身（AGPL-3.0）
- 对核心的 sed 修改（补丁命令公开，不影响竞争力——都是通用优化）
- `global.__proma__` 桥接层（一个函数引用列表，无商业逻辑）

### 可以闭源的部分
- 所有独立模块（独立文件/独立进程）
- 后端服务（注册、计费、云同步）
- 专有 Skill 和 MCP 工具内容
- 品牌素材和 UI 主题

### 合规红线
- ❌ 不能把闭源代码直接写进开源模块文件（如直接在 `agent-orchestrator.ts` 里写注册逻辑）
- ✅ 可以通过 IPC/MCP/HTTP 从闭源模块调用开源核心
- ✅ 可以通过 `global.__proma__` 等桥接访问核心 API（参考商业版 15 个闭源模块）
- ✅ 可以单独收费，不构成对 Proma 核心的收费分发

### 插件模式的合规性（已验证）

**你的闭源插件不构成 AGPL 衍生作品。** Proma 商业版自身就是最好的先例：

```
商业版 main.cjs
     │
     │  require("./your-plugin.cjs")  ← 一行注入
     │
     ▼
你的闭源插件（独立 .cjs 文件）
     ├── 通过 global.__proma__ call 核心 API（标准接口）
     ├── 时间线剪辑 / 专属 MCP 工具 / 注册激活
     └── 完全闭源 + 独立收费
```

**
| 类比 | 说明 |
|---|---|
| **Photoshop 插件** | 给 PS 写插件不需要开源代码给 Adobe |
| **VS Code 扩展** | 闭源扩展通过公开 API 通信，不构成衍生作品 |
| **Proma 商业版自身** | 15 个闭源模块 (cloudAuth/sync/billing) 挂在核心旁 |
| **WordPress 插件** | 闭源付费插件通过 WordPress API 运行，完全合法 |

### 分发与收费的三种模式

| 模式 | 做法 | 合规性 |
|---|---|---|
| **纯插件分发** | 只分发你的 `.cjs` 插件文件，用户自己装到 Proma | ✅ 完全闭源，完全合法 |
| **预装版分发** | 把插件 + Proma 核心打包成安装包 | ⚠️ 核心改动用 sed 补丁须公开（不影响竞争力），插件仍可闭源 |
| **SaaS 模式** | 跑自己的服务器，用户用客户端连 | ✅ 不受 AGPL 约束（未"分发"代码） |

### 三方法律关系

```
你（插件作者）
  → 卖闭源插件给用户
  → 不捆绑分发 Proma 核心

用户
  → 从官方渠道获取 Proma
  → 自行加载你的插件

Proma 官方
  → 提供 AGPL 源码 / 商业授权
  → 不限制用户使用第三方插件
```

## 五、技术架构

### 开发版工作流（已验证）

```
D:\Proma\ (商业推广版，不动)
D:\Proma-dev\ (你的开发版)
  ├── 解包 ASAR
  ├── main.cjs (商业版 + sed 补丁)
  ├── proma-dev-patches.cjs (自有插件)
  └── renderer/ (商业版 + 自有补丁)
```

### 外部 MCP 服务（下一步）

```
外部系统
  ├── Claude Code (VS Code)
  ├── 自定义脚本
  └── CI/CD 流水线
       │
       ▼ MCP stdio/HTTP
  proma-session-mcp-server (独立进程，闭源)
       │
       ▼ 读写
  ~/.proma/ (会话/渠道/配置数据)
```

## 八、关键风险

| 风险 | 等级 | 应对 |
|---|---|---|
| AGPL 合规争议 | 中 | 严格区分模块边界，重大发布前做合规审查 |
| Proma 核心大版本升级 | 中 | 补丁体系已自动化基础，核心升级后一周内可适配 |
| SDK 变更（Anthropic） | 低 | 商业版也在用同一 SDK，有社区力量分摊 |
| 盈利模式验证 | 高 | Phase 1 即可通过手动服务验证需求，不等到全自动化 |
