## ISS-001 `remote_create_session` 不传 workspace_id 时默认用调用方工作区 slug，跨实例调用必失败

- **状态**：🟡 已规避（有 workaround，根因未修）
- **严重度**：中（影响所有跨实例会话创建，但不破坏数据，有明确规避方法）
- **类型**：MCP 接口设计陷阱 / 文档缺口
- **发现日期**：2026-07-03

### 现象
调用 `mcp__remote-session__remote_create_session` 创建远程实例（如 Pro）会话时，若不传 `workspace_id` 参数，必报错：
```
E_WORKSPACE_NOT_FOUND: workspace_id "proma" not in workspace index.
Valid ids: <目标实例自己的 workspace_id>。Use list_workspaces to see all.
```

### 根因
该工具在未传 `workspace_id` 时，默认取**调用方当前工作区**的 slug（本工作区是 `proma`）作为目标远程实例的 workspace_id。但远程 Pro 实例的工作区索引里**没有** `proma` 这个 slug（Pro 只有自己的默认工作区，id 形如 `eb5e3f9c-…`），因此必然找不到。

工具 help_hint 提示「Use list_workspaces to see all」，但**没有**用目标实例的默认/第一个工作区做兜底——把"该传哪个 id"的负担完全丢给了调用方，且默认值在跨实例场景下永远错。

### 规避方案（当前必做）
跨实例创建会话前，**先调 `remote_list_workspaces(instance=<目标>)` 拿到目标实例自己的 workspace_id，再显式传入** `remote_create_session(workspace_id=...)`。

### 理想修复（待 patch）
在 `remote_create_session`（及同类 remote_* 写操作）中：当未传 `workspace_id` 时，自动调用目标实例的 `list_workspaces` 取**第一个/默认工作区**兜底，而不是套用调用方 slug。

### 实测依据
2026-07-03 20:34 在 Pro 实例（`127.0.0.1:19877`）端到端验证远程会话操作时踩到：
- 不传 workspace_id → 报错 `E_WORKSPACE_NOT_FOUND`（默认用了 `proma`）
- 传 Pro 实例 workspace_id `eb5e3f9c-d16c-419d-afcb-19e89c4114ee` → 创建成功（session `4e1e8e26`），后续 `remote_send_message`（GLM-5-turbo 准确回复）/ `remote_get_session_context` / `remote_archive_session` 全链路通过。

**附带结论**：Pro 实例远程会话操作整体可用，仅此创建入口的默认值有坑。

## ISS-002 Tree 面板点击同名 title 会话切换失效（navigate-to-session）

- **状态**：🔴 待解决
- **严重度**：中（影响 tree 面板点击 leaf 切 Proma 会话；仅同名 title 会话场景，日常较少但不便）
- **类型**：UI 交互 bug / IPC 切换链路
- **发现日期**：2026-07-03

### 现象
在 tree 面板（`proma-tree-view.js`）点击 leaf/commander 节点，期望切换到对应 Proma 会话（侧边栏 + 聊天区）。但当两个会话 **title 相同、session_id 不同**时，点击切换不动——目标会话不激活。tree 面板内部 detail 切换正常（用 leaf_id，不受影响）。

### 根因
`navigate-to-session` handler（patches.cjs）已传 `{ sessionId, title }`（与 Proma 内置 `openAgentSession(sessionId, title)` 一致，main.cjs 行 572367），通过 `tray:open-agent-session` 事件让 renderer 切换。补 title 后仍不行，**疑似 Proma renderer 的会话切换/高亮逻辑用 title 匹配 tab**（同名歧义，找第一个），而非纯 sessionId。renderer 在打包 bundle（`index-*.js`），无法直接改。

### 规避方案（当前）
- 同名会话场景手动在 Proma 侧边栏点击目标会话切换
- 或避免给会话起完全相同的 title

### 理想修复（待查）
绕开 `tray:open-agent-session`（带 title，renderer 可能用 title 找 tab），找 Proma **纯 sessionId-based 切换 IPC**：
- 候选 `quick-task:open-session`（main.cjs 行 570190，待验证参数格式 + 是否通用）
- 或 main.cjs 其他 setActive 通道（grep `setActiveTabId` / `open-session` / `activate-session`）
- 验证哪个 IPC 让 renderer 用 sessionId 而非 title 切换

### 实测依据
2026-07-03 20:32 tree 面板改造收尾验证：
- 补 title 前：同名切换不动
- 补 title（`{sessionId, title}`，与 Proma 内置一致）后：**仍不动**（反证 renderer 非因缺 title，疑似主动用 title 匹配）
- tree 内部 detail 切换正常（leaf_id，不受影响）
- 非同名会话切换正常

详见 note.md 2026-07-03 20:32 条目 + patches.cjs `navigate-to-session` handler 注释（行 ~1899）。
